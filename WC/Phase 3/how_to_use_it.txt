How to run it

1. Start the cluster (verbose logs on, for the screenshots):

bash
docker compose up -d --build
docker compose exec client python client.py blood sample   # repeat a few times
docker compose logs -f load-balancer server1 server2 server3

This is the evidence for item 8a. Run it with LB_VERBOSE=1 SERVER_VERBOSE=1 set before docker compose up to see a log line per request.

2. Run the three configurations with identical settings. Turn verbose logging off for these runs:

bash
# (a) 1 server, no load balancer
docker compose up -d --force-recreate
docker compose exec -e SERVER_HOST=server1 -e CONFIG_LABEL=single client python benchmark_phase3.py

# (b) 3 servers, least connections
LB_ALGORITHM=least_connections docker compose up -d --force-recreate load-balancer
docker compose exec -e CONFIG_LABEL=least_connections client python benchmark_phase3.py

# (c) 3 servers, least response time
LB_ALGORITHM=least_response_time docker compose up -d --force-recreate load-balancer
docker compose exec -e CONFIG_LABEL=least_response_time client python benchmark_phase3.py

# combined figures
docker compose exec client python compare.py

3. Make the two algorithms distinguishable. Give server3 an artificial delay and repeat (b) and (c) with new labels:

bash
SLOW_DELAY_MS=20 docker compose up -d --force-recreate server3
LB_ALGORITHM=least_connections docker compose up -d --force-recreate load-balancer
docker compose exec -e CONFIG_LABEL=lc_slow3 client python benchmark_phase3.py
LB_ALGORITHM=least_response_time docker compose up -d --force-recreate load-balancer
docker compose exec -e CONFIG_LABEL=lrt_slow3 client python benchmark_phase3.py

Compare the server_distribution column in summary.csv. Least response time should send fewer requests to the slow replica, while least connections should shift load more mildly. Run these in a separate results batch, because compare.py plots every folder it finds.

4. If 3 servers show no gain over 1. Cache hits are very cheap, so the LB, Redis and the Python client can be the bottleneck. Try BYPASS_CACHE=1 (set before docker compose up) with the larger deadpool text (-e TEXT_NAME=deadpool), or raise the rates. Whatever you observe, explain it in the report.
